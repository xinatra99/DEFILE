DEFILE · Firmware Reverse Engineering and Security Analysis

Dissect the firmware. Expose the weakness.

DEFILE is a self-hosted firmware analysis platform for binary inspection, vulnerability research, embedded systems analysis, and security intelligence. It combines multi-architecture disassembly, CVE correlation, heuristic taint analysis, cross-binary call graphs, and optional AI-assisted investigation. Analysis runs locally; enabling an external AI provider sends selected scan evidence to that provider.

Why DEFILE

Static analysis, backed by evidence

Every finding carries a confidence score, a code location, and (where relevant) a taint path — never a vague "might be an issue."

Multi-arch RE, no live device needed

x86/x86_64, ARM, ARM Thumb-2, AArch64, MIPS LE/BE — pure static disassembly + import resolution, with function-boundary recovery even on stripped binaries.

CVE correlation you can trust

Curated offline DB + cve-bin-tool (NVD/OSV/RedHat/GitLab/Curl, 350+ components); kernel version gets its own precise correlator to dodge third-party checker regex gaps.

Taint + cross-binary tracing

Source-to-sink reachability through the call graph, tracing CGI/script calls into shared-library sinks — not just single-file analysis.

AI-assisted triage (new)

On-demand AI analysis of a completed scan's findings — false-positive triage, exploit-chain correlation, remediation priority — with any OpenAI-compatible provider.

Self-hosted, air-gap friendly

The Go service uses standard-library HTTP and a pure-Go SQLite driver; the frontend vendors Alpine.js locally with no build step. Local analysis can use cached vulnerability data without a live network connection.

CLI and REST API, same core

Script a one-shot run, or stand up the service with a queue + web dashboard to batch an entire firmware corpus.

AI-Assisted Analysis of Scan Results

An optional AI layer on top of the rule-engine findings — it doesn't re-scan the firmware, it just helps you read the existing results faster.

  • On-demand, no surprise costOne button on the report page — you choose the provider and the moment. It never calls out automatically after every scan.
  • Any OpenAI-compatible providerCustom Host URL — self-hosted gateways (one-api / newapi / vLLM / Ollama) or a vendor API, multiple profiles at once.
  • Pick the model, never type itEnter Host + Key, fetch /models once, pick from the list — saving is blocked until that succeeds, eliminating typos at the root.
  • Keys encrypted at restAES-256-GCM + a local random key file, stdlib only; API responses only ever show the last 4 characters.
  • Prompt-injection awareText extracted from firmware (descriptions/pseudocode) is explicitly framed as evidence, not instructions; output is rendered as plain text only, never parsed as HTML.

Quick Start

Run your first scan in a few minutes

Full environment setup (cross-compilers, Ghidra/JDK pitfalls) is in the repo's ENVIRONMENT.md.

Runs on Linux and macOS, Apple Silicon or Intel. The analysis runs on your own machine, so it doesn't matter whether the firmware is ARM or MIPS.

1 · Analysis core

# Install with pip in a virtual environment
apt-get install -y python3-capstone python3-pyelftools
pip install cve-bin-tool   # Required for broad CVE correlation
pip install yara-python    # Optional

python3 -m defile.cli analyze ./rootfs \
  --json report.json --md report.md --sbom sbom.json

2 · Service layer (optional — REST API + Web UI)

# Go 1.25+
cd service && go build -o defile-service .

./defile-service -addr :8080 \
  -core /path/to/DEFILE -data ./.data \
  -user admin -pass 'change-me'
# open http://localhost:8080

On a Mac

Swap the apt line above for brew and the rest is the same. The Go service is pure Go — SQLite included — so it builds with no Xcode and no CGO on both arm64 and Intel. Only the Ghidra decompile step needs a JDK 17; skip it if you're not decompiling.

# Homebrew:https://brew.sh
brew install python@3.12 go

python3 -m venv .venv && source .venv/bin/activate
pip install -e . cve-bin-tool

# Pure Go; builds on arm64 and Intel
cd service && go build -o defile-service .

About cve-bin-tool's first run

It maintains its own local CVE database (NVD/OSV/RedHat/GitLab/Curl, ~1GB+) — the first scan on a machine syncs it and needs network access, so expect it to be slow; later scans reuse the local cache. Without it, analysis still runs, just with CVE correlation degraded to the small built-in curated DB, with a clear warning in the report.

⚠ Authorized Use Statement

Only analyze firmware you own or have written authorization to assess. This is a defensive security research tool and assumes no liability for misuse.

On Accuracy

Decompilation-free static analysis is inherently heuristic. Every finding carries a confidence score — precise call-site detections (0.8) rank above import-presence (0.4) and call-graph taint reachability (0.5). Taint findings are candidate paths for analyst validation, not proven exploits.
